# STABLE · AI Fall Assessment System

노인 낙상 기능평가를 보조하는 React + TypeScript 연구·교육용 웹앱입니다. 검증된 AI 낙상 예측 모델이나 의료 진단 도구가 아닙니다. 실제 고령자 대상 측정 정확도는 아직 검증되지 않았습니다.

## 실행

Node.js 22.12 이상 또는 24 LTS를 권장합니다. 검증 환경은 Node 24.22.1입니다.

```sh
npm install
npm run dev
npm run test
npm run build
```

잠금파일 기반 재설치는 `npm ci`를 사용합니다. 이 클라우드처럼 기본 npm 캐시에 쓸 수 없는 환경에서는 `npm ci --cache /tmp/yoodong-npm-cache`를 사용하세요. 개발 서버 기본 포트는 5173이며 프로덕션 출력은 `dist/`입니다. 개발·빌드 전 스크립트가 설치된 MediaPipe 패키지의 WASM/JS를 `public/wasm`으로 복사합니다. 해당 생성물은 Git에서 제외하고 Vercel 빌드에 포함합니다.

모든 검사 데이터는 현재 탭의 메모리에만 존재합니다. 새로고침·종료 전에 내보내세요. 데모용 가상 결과나 원본 영상은 저장하지 않습니다.

## 사용 순서

1. 대시보드에서 균형 또는 TUG 검사를 선택합니다.
2. 익명 대상자 코드, 연령, 날짜, 검사자 코드를 입력합니다. 실명이나 연락처 등 식별 정보는 수집하지 않습니다.
3. 카메라를 선택·연결하고 밝기·전신·발의 가시성을 확인합니다. 카메라 변경 전 기존 카메라를 종료합니다. HTTPS 또는 localhost가 필요합니다.
4. 검사자가 실제 검사 환경과 자세를 확인한 뒤 타이머를 시작합니다. 자동 추적이 실패해도 수동으로 측정할 수 있습니다.
5. 검사 완료 또는 중단 후 결과·이력·추적 품질을 확인하고 CSV/JSON으로 다운로드합니다. JSON에는 프레임별 33개 랜드마크와 상대 밀리초 타임스탬프가 포함됩니다.

## 4-Stage Balance Test

CDC STEADI 절차를 참고해 나란히, 반일렬, 일렬(Tandem), 한 발 서기의 순서로 각 10초를 측정합니다. 검사자는 근접 보호하고 필요 시 자세 준비를 돕습니다. 타이머는 대상자가 지지 없이 자세를 유지할 준비가 되고 검사자가 확인했을 때 시작합니다. 고정된 정면 카메라로 전신과 발을 촬영합니다. 정면 영상에서 발 앞뒤 관계를 자동 확정하지 않습니다.

각 단계는 `performance.now()`를 기준으로 최대 10초를 기록합니다. 10초 목표 미달, 균형 상실 판정, 외부 지지 또는 검사자 중단 시 이후 단계를 진행하지 않습니다. 마지막 단계 전까지 10초를 달성하면 다음 자세를 수동 확인한 후 진행합니다. 재검사는 진행 중 자료를 명시적으로 초기화합니다. 추적 신뢰도가 낮아져도 표준 타이머는 임의로 멈추지 않으며 검사자에게 확인을 요청합니다.

고관절 중심 좌우 변위 범위가 최초 유효 어깨너비의 0.25를 넘으면 탐색적 흔들림 이벤트를 기록합니다. 이 임계값은 임상 검증되지 않았고 균형 상실 자동 판정이 아닙니다. 검사자의 균형 상실 판정과 별도 이력으로 저장합니다.

## Timed Up and Go (TUG)

팔걸이 의자와 실제 바닥 3m 표시를 준비합니다. 평소 신발과 통상 보조기를 사용하고, 앉은 상태에서 검사자 “시작” 신호에 일어나 평소 속도로 3m 보행, 회전, 복귀, 다시 앉기를 수행합니다. 의자와 이동 경로가 보이는 측면 또는 대각선 촬영을 권장합니다.

표준 시간은 검사자의 시작 신호부터 다시 앉음을 확인한 시점까지입니다. 상태 순서는 다음과 같습니다.

`READY → SIT_TO_STAND → WALK_OUT → TURN → WALK_BACK → STAND_TO_SIT → COMPLETED`

검사자가 다음 구간 버튼이나 수동 구간 선택으로 상태를 확인합니다. 자동 후보는 시간이나 상태를 직접 바꾸지 않습니다. 최초 8개 이상 유효 프레임과 400ms 이상 구간을 요구하며, 무릎각·영상 고관절 높이 변화로 일어서기/앉기, 영상 x축 이동 반전으로 방향 전환, 지속 이동으로 복귀를 탐색적으로 제안합니다. 정면 깊이 이동, 가림 또는 시점 변화에서 후보가 없거나 잘못될 수 있습니다. “검사자 확인 필요”로 표시하고 수동 완료가 가능합니다.

구간 시간은 **검사자가 버튼을 누른 시점 사이의 간격**입니다. 구간 표시를 생략하면 전체 시간이 한 구간에 포함될 수 있으므로 실제 생체역학적 분절 시간으로 해석하지 마세요. 전체 시간 수동 보정은 원래 구간·자동 후보 시점을 보존하고 이전 값, 새 값, 사유를 이력에 남깁니다. 따라서 보정 후 구간 합계와 전체 시간이 다를 수 있습니다.

## 영상 분석과 한계

- `@mediapipe/tasks-vision` Pose Landmarker VIDEO 모드, CPU 추론, 단일 사람, 최대 약 12fps로 실행합니다. 중복 프레임은 처리하지 않습니다.
- 설치 버전의 공식 TypeScript API(`FilesetResolver.forVisionTasks`, `PoseLandmarker.createFromOptions`, `detectForVideo`, `close`)에 맞춰 구현했습니다. 공식 웹 문서 URL은 아래와 같습니다. 현재 클라우드에서는 문서 사이트 접근이 네트워크 정책으로 차단되어 온라인 문서 대조는 미완료입니다.
- `x × (영상 너비/높이)`와 `y`로 픽셀 종횡비를 보정한 뒤 2D 벡터 각도를 계산합니다. 좌측 어깨·고관절·무릎·발목으로 고관절/무릎 내각을 계산하며 체간 각도는 양측 어깨/고관절 중심을 연결한 선의 수직 대비 각도입니다. 3D 또는 임상 정확도를 주장하지 않습니다.
- 고관절 중심·어깨 중심·발목/발끝 평균점의 좌우 범위를 해당 검사 또는 단계의 최초 유효 프레임 어깨너비로 나눕니다. 정규화 방법과 원본 좌표를 저장합니다. 단계마다 기준 어깨너비가 다를 수 있습니다. 발의 평균점은 개별 발 이동을 상쇄할 수 있어 JSON 개별 궤적도 확인해야 합니다.
- 이 값은 화면상 변위이며 COP, 실제 COM, 실제 거리, 보행속도(m/s)가 아닙니다. 실제 3m는 검사자가 표시해야 합니다. 공간 보정과 별도 검증 전 영상 좌표로 실제 거리나 속도를 산출하지 않습니다.
- 필수 랜드마크 최소 visibility 0.6, 화면 경계 내 위치를 유효 추적 기준으로 사용합니다. 저조도·가림·화면 이탈·검출 실패를 안내하고 데이터에 유효 여부를 기록합니다. visibility는 임상 정확도 확률이 아닙니다. 500ms 이상 프레임 간격과 유효 프레임 비율을 결과에 표시합니다.
- 비디오는 화면에만 표시하고 Canvas에는 스켈레톤만 그립니다. 좌우 반전은 비디오와 Canvas에 함께 적용합니다. 좌측 신체는 청록색, 우측은 주황색입니다.
- 화면 해제·카메라 종료 시 모든 스트림 트랙과 MediaPipe 인스턴스를 해제합니다. 비동기 연결이 취소된 후 도착한 스트림도 종료합니다.
- 유효 추적 데이터가 없으면 시간만 내보내며 운동학 값은 결측치로 남깁니다. 임의 값을 채우지 않습니다.

## 모델 및 네트워크

WASM은 같은 배포의 `/wasm`에서 읽습니다. 모델은 Google 공식 저장소의 버전 1 lite float16 task를 읽습니다.

`https://storage.googleapis.com/mediapipe-models/pose_landmarker/pose_landmarker_lite/float16/1/pose_landmarker_lite.task`

모델 다운로드 요청만 외부로 나가며 카메라 영상이나 좌표는 전송하지 않습니다. 모델 다운로드·WASM 초기화가 실패하면 오류와 재시도 버튼을 표시하며 수동 검사 기능은 유지합니다. 모델을 신뢰할 수 있는 경로로 별도 확보한 경우 빌드 시 `VITE_POSE_MODEL_URL`로 로컬 배포 경로나 승인된 URL을 지정할 수 있습니다. 원본 영상 저장은 구현하지 않았고 향후 별도 동의·연구윤리 검토가 필요합니다.

현재 클라우드의 `storage.googleapis.com` 허용이 적용되지 않아 실제 모델 로딩·사람 영상 추론은 검증하지 못했습니다. 이 제약이 해소된 후 실제 사람의 정면/측면 영상으로 스켈레톤 정렬·추론·촬영 조건별 품질을 확인해야 전체 MVP 검증이 완료됩니다.

## 선별 참고 기준

- 완료된 TUG ≥12초: CDC STEADI의 낙상위험 증가 관련 선별 소견
- 실제 실시한 Tandem에서 10초 유지 실패: CDC STEADI의 낙상위험 증가 관련 선별 소견

미완료 TUG, 미실시 Tandem에는 해당 기준을 적용하지 않습니다. 기준 미해당도 위험 없음의 진단은 아닙니다. 임의 AI 위험점수, 확률, 예측 정확도는 산출하지 않습니다.

## 검증

```sh
npm run test
npm run build
# 별도 터미널에서 npm run dev 실행 후, Chromium 설치 환경:
npm run test:e2e
# 선택 설정: CHROMIUM_PATH=/path/to/chromium TEST_BASE_URL=http://localhost:5173
```

Vitest는 각도 수학, 종횡비 보정, 추적 실패, 정규화, 타이머, 단계 중단, 상태 전이, 합성 랜드마크 동작 후보, 반복 검사 초기 자료, 출처별 구간 기록, 수동 보정 보존, CSV/JSON, 카메라 트랙 종료를 검사합니다. 브라우저 스모크 테스트는 가짜 카메라 장치로 타이머/수동 검사와 내보내기를 검증합니다. 제품에 테스트 결과를 삽입하지 않습니다. 실제 사람의 추론 정확도를 검증하는 테스트는 아닙니다.

실제 노인 대상 후속 검증 계획: 수동 스톱워치와 동시 비교, 반복측정, MAE, RMSE, Bland–Altman 일치도, ICC 신뢰도 분석. 촬영 방향·거리·조명·보조기·가림별 오차와 실패율을 사전에 정한 절차로 평가합니다. 아직 측정된 정확도 수치나 통계 결과는 없습니다.

## GitHub / Vercel

기존 저장소: https://github.com/yoodong-phd/Yoodong-fall

기존 Vercel 프로젝트 `ai-fall-assessment`의 설정:

| 항목              | 값              |
| ----------------- | --------------- |
| Framework Preset  | Vite            |
| Root Directory    | `./`            |
| Build Command     | `npm run build` |
| Output Directory  | `dist`          |
| Production Branch | `main`          |

`vercel.json`에 Vite 및 SPA fallback을 설정했습니다. `main` Push 후 연결된 프로젝트가 자동 빌드해야 합니다. **이 파일만으로 Vercel의 Git 연결 상태나 배포 성공을 보장하지는 않습니다.** 예상 URL은 https://ai-fall-assessment.vercel.app 입니다. 모델 파일·WASM·JS 자산은 SPA fallback에서 제외합니다.
